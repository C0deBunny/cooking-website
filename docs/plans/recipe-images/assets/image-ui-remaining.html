8

Crop dialog chrome default: Dialog, Cancel → idle

Both dialog.tsx and sheet.tsx are installed. The second half — what Cancel means — matters more than the first.

Dialog default

Centred modal, Escape and backdrop close it.

A square viewport wants a square-ish container, and a centred box gives it the most room on a desktop.

On a phone a centred modal with a drag surface fights the browser chrome for space.

Sheet

Slides from the bottom, full width.

Better on a phone, and the drag surface gets the full width. Pairs with question 5 if the answer there is "responsive".

On a desktop a bottom sheet for a square is mostly wasted width, and it reads as a mobile idiom on a desktop-first route.

What Cancel means — the part that actually matters

No upload has happened when the dialog is open, so there is genuinely nothing to preserve except the picked File.

Cancel → idle default

idle→pick→cropping→cancel→idle

Nothing retained. Re-cropping means re-picking the file — one extra click, and no File is held in state, which is what decision 4 was careful about.

Cancel → keep the file for a retry

idle→pick→cropping→cancel→picked, not cropped→reopen→cropping

Saves a click, but invents a fourth field state holding a File that toPayload cannot resolve — the exact shape decision 4 rejected. And under B4's union it has no status to live in.
