    What this buys, beyond looking better:
    
            
    
              The crop warning, the aspect check that drives it, and the whole "which surface frames it how" question all disappear — because the file on disk is already the final framing. Decision 12's "the preview must not
              lie" stops needing mitigation and becomes true by construction, which is the same move the plan already makes for the sanitiser rule.
            
    
          
    

          
    
            
    The EXIF trap mutates rather than going away.
    
            
    
              The <img> in this dialog applies EXIF rotation automatically — browsers default to image-orientation: from-image. createImageBitmap does not, unless passed the flag. So
              a portrait phone photo would be cropped correctly on screen and then drawn rotated and offset to the canvas: the crop rect is computed against one orientation and applied to another. Worse than the original risk,
              because the output is subtly wrong rather than obviously sideways.
            
    
            
    The fix is an ordering rule: decode with createImageBitmap(file, { imageOrientation: "from-image" }) first, paint that bitmap into the dialog, and never put the raw File in an
              <img>. Then one orientation exists everywhere.
    
          
    
        
    
      
    

      
    
        
    
          
    What it costs to build
    
          
    Measured against this prototype, which is the whole interaction.
    
        
    
        
    
          
    
            The pipeline change is one line. The plan already calls drawImage; a crop is the same call with the 9-argument source-rect form. Nothing about compression, webp, the bucket, the payload,
            save_recipe() or the path convention changes at all.
          
    
          
    
            File→
            createImageBitmap(file, {imageOrientation})→
            crop dialog → {sx, sy, size}→
            drawImage(bmp, sx, sy, size, size, 0, 0, 1200, 1200)→
            convertToBlob(webp)→
            upload
