The header band, light vs dark

The plan defers dark mode because the tinted band "nearly vanishes at the 34% mix that works in light". Rendered against the real tokens, the opposite happens. Dark --accent is oklch(0.78 …) — a light tan — sitting on a oklch(0.18 …) page, so the same 34% mix that is a whisper in light is a slab in dark.

The arithmetic

Oklab interpolates lightness close to linearly, so the mix result is predictable without rendering it. Rendering it is for the taste call, not the maths.

theme --accent L --background L 34% mix → L ΔL vs page
light 0.901 0.980 0.953 0.027
dark 0.780 0.180 0.384 0.204  (7.5×)

What this changes in the plan

  • The recorded reason for deferring dark mode is backwards. Decision 14 says the band "nearly vanishes"; it is 7.5× louder than in light. Whatever gets decided, that sentence should not stay in the record as written.
  • The fix is one token, not a dark-mode pass. A dark: variant on the band's mix percentage is the whole change — the cards, hero, borders and orange all survive dark untouched, which is what the original mock-up actually established.
  • The theme toggle ships on every route, so this is reachable on day one by anyone who clicks it. That makes it a shipping defect rather than a deferred enhancement — the same argument that was accepted for the phone layout and rejected there.
